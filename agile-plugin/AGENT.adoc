= AGENT.adoc — Agile Gradle

_Produit_ : Plugin Gradle de pilotage agile assisté par IA — 7 ateliers de cadrage + backlog + sprints
_Licence_ : Apache 2.0 (OSS)
_DAG_ : N4 — Plugin Gradle de pilotage transverse (orchestration métier)
_Dépendance_ : runner-gradle (compileOnly, lecture état DAG), workspace-gradle (lecture état workspace), langchain4j (LLM prompting)

== Principe

Le plugin `agile` implémente le **pilotage agile du workspace** assisté par IA,
en s'appuyant sur la méthodologie des **7 ateliers de cadrage**
(source : `0054_memo_cadrage_post.adoc`).

L'IA (gpt-oss:120b-cloud via langchain4j) assiste chaque atelier en :
- Posant les bonnes questions au bon moment
- Structurant les réponses dans le format attendu
- Générant les livrables AsciiDoc de chaque atelier
- Détectant les incohérences entre ateliers (vision vs backlog, personas vs US)

Les 7 ateliers de cadrage :

=== Atelier 1 : Vision
QQOQCP (Qui, Quoi, Où, Quand, Comment, Pourquoi) + Product Vision Board
(Target Group → Needs → Product → Business Goal → Vision en une phrase).

=== Atelier 2 : Personas / Parcours utilisateurs
Définir les personas cibles et leurs parcours :
Qui utilise ? → Que veut-il faire ? → Comment le fait-il ?

=== Atelier 3 : Zoning / Storyboard / Sitemap
Architecture de l'information visuelle : zones, flux, arborescence.

=== Atelier 4 : Wireframe / Moodboard
Maquettes fonctionnelles + direction créative.

=== Atelier 5 : Story Mapping / User Stories
Cartographie des user stories + priorisation :
« En tant que <persona>, je veux <objectif> afin que <raison>. »

=== Atelier 6 : Backlog
Construction et priorisation du backlog produit (Atlassian method).

=== Atelier 7 : Technique et Architecture
Stack technique, architecture, contraintes, non-fonctionnels.

Pipeline complet :
  Prompt atelier ──→ IA (LLM) ──→ questions structurantes ──→ réponses humain ──→ livrable AsciiDoc ──→ enrichissement cross-atelier

Cas d'usage MVP0 :
- Cadrage assisté d'un nouveau plugin Gradle (ex: document-gradle a été cadré avec 7 ateliers)
- Tableau de bord EPICs cross-borough (avancement %, statut, priorité)
- Rapport de sprint : sessions réalisées, vélocité, tendances
- Détection de blocages : dépendances non satisfaites, EPICs en retard
- Génération du rapport de jalon MVP0

== Loi de l'Économie d'Encre — Non-Répétition des Opérations Coûteuses

*PRINCIPE* : Une opération coûteuse (LLM, inférence cloud, assistance IA des 7 ateliers de cadrage) qui a déjà produit un résultat *valide et persistant* NE DOIT PAS être ré-exécutée sur la même entrée. Le résultat existant est la vérité ; le re-calcul est un gaspillage de tokens/crédits API/temps de build. L'IA n'est pas un générateur idempotent gratuit — c'est un service metered. Re-appeler le LLM pour un atelier déjà cadré et dont le livrable `.adoc` est valide : ce geste consomme du token sans produire de nouvelle connaissance. L'économie d'encre est la condition de viabilité économique du pipeline agentique MVP0.

*RÈGLE* :
. Avant toute opération coûteuse, **vérifier l'existence d'un artefact résultat** (`vision.adoc`, `personas.adoc`, `zoning-sitemap.adoc`, `wireframes.adoc`, `story-mapping.adoc`, `backlog.adoc`, `architecture.adoc`, cache disque).
. Si l'artefact existe et couvre l'entrée demandée → **réutiliser sans ré-invoquer**.
. Seul le **delta** (atelier non complété, réponses modifiées, enrichissement cross-atelier) doit être calculé — jamais l'ensemble.
. Ne **jamais écraser** un résultat validé par un re-calcul identique. L'écrasement est un symptôme de non-idempotence économique.
. L'invalidation est **explicite et ciblée** (réponses atelier modifiées, atelier ajouté), jamais globale par défaut.

*ANTI-PATTERNS SPÉCIFIQUES AGILE* :
. *Re-cadrage systématique* : re-appeler le LLM sur les 7 ateliers parce qu'un seul livrable a été édité manuellement.
. *Re-dashboard inconditionnel* : regénérer `agileDashboard` / `agileSprint` / `agileVelocity` sans comparer les metadata.json sources avec le dernier rapport généré.
. *Cache-busting silencieux* : un `writeText()` qui écrase le livrable `.adoc` d'un atelier avant même d'avoir lu l'existant.

*PROTECTION* :
. Lecture avant écriture : charger le livrable `.adoc` existant avant de re-appeler le LLM ; comparer hash des réponses atelier avec hash stocké en metadata du livrable.
. Delta atelier : ne régénérer que les ateliers dont les réponses ont changé ou qui manquent (hash comparison).
. `DisableCachingByDefault` ne dispense pas de l'idempotence applicative — Gradle ne sait pas ce qu'est un "atelier déjà cadré", seul le domaine le sait.

*RÉFÉRENCE* : Source canonique — `bakery-gradle/bakery-plugin/AGENT.adoc` section "Non-Répétition des Opérations Coûteuses — Loi de l'Économie d'Encre" (Session 153). Portée transverse : 10 boroughs LLM metered. Potentiel 50-80% d'économie LLM sur le pipeline MVP0 complet.

== Tâches Principales

  ./gradlew agileWorkshop        → lancer un atelier de cadrage assisté par IA (1 à 7)
  ./gradlew agileBacklog         → lister tous les EPICs avec statut, priorité, dépendances
  ./gradlew agileSprint          → générer le rapport de sprint courant
  ./gradlew agileVelocity        → calculer et afficher la vélocité par borough
  ./gradlew agileMilestone       → état d'avancement vers le jalon MVP0
  ./gradlew agileDashboard       → générer un dashboard HTML de l'avancement global
  ./gradlew check                → tous les tests (unitaire + fonctionnel)

== Tests

Le projet utilise JUnit5 et GradleTestKit.
Toute modification de code source DOIT passer `./gradlew check`
(sauf permission contraire).

== Stack

- Kotlin — DSL Gradle
- langchain4j — LLM prompting (gpt-oss:120b-cloud) pour assistance ateliers
- Jackson — parsing des metadata.json de chaque borough
- AsciidoctorJ — génération des livrables et rapports AsciiDoc/HTML
- runner-gradle — dépendance compileOnly, lecture état DAG N3
- workspace-gradle — dépendance compileOnly, lecture état workspace N4

== Ne remplace PAS opencode

Le plugin est invoqué PAR opencode (via tool use).
L'IA assiste le cadrage, mais les décisions de priorisation,
les choix architecturaux et les ajustements de planning restent humains.
